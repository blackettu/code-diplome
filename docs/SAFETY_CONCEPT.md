# Концепция безопасности

Слой принятия решений намеренно разделён на этапы:

```text
DecisionPolicy -> ActionPlan -> SafetyGate -> robot/simulator adapter
```

Политики не могут пометить действие как исполнимое. Они только предлагают
объекты `ActionCommand`. `SafetyGate` проверяет команду по `SceneState`,
телеметрии робота и `SafetyLimits`.

Решения безопасности:

```text
ALLOW_SIMULATION
ALLOW_DRY_RUN
ALLOW_HARDWARE_IN_LOOP_POINTER
ALLOW_SUPERVISED_MARK
BLOCK_REVIEW_REQUIRED
BLOCK_CALIBRATION_REQUIRED
BLOCK_INTERLOCK
BLOCK_UNSAFE_TARGET
BLOCK_SYSTEM_ERROR
```

Ограничения по умолчанию отключают реальные действия. Блокирующими условиями
являются неизвестные растения, неоднозначные ячейки, посторонние объекты,
недействительная калибровка, робот без homing, отказ межблокировки, запрещённые
зоны, цели вне кассеты и недостаточное расстояние до сохраняемых сеянцев.

Даже если будущий supervised-режим явно разрешит реальное действие,
`SceneState.safety.software_safe_mode` и `SceneState.safety.enclosure_closed`
должны оставаться истинными. Иначе `SafetyGate` блокирует команду с причинами
`software_safe_mode_disabled` и/или `enclosure_not_closed`. Команда реального
действия классифицируется как `BLOCK_UNSAFE_TARGET` с причиной
`real_action_not_allowed` до учёта подтверждения оператора; подтверждение не
может превратить отключённый путь реального исполнительного механизма в обычное
событие проверки.

Доступ HIL защищён артефактами `HardwareInLoopReview`. Текущий проект разрешает
только `hardware_in_loop_pointer` / `pointer_only`; проверка артефакта явно
отклоняет `allow_real_actuation=true`. Если указана измеренная
`positioning_error_p95_mm`, она не должна превышать `max_error_p95_mm`; иначе
проверка HIL завершается ошибкой до открытия последовательного порта. HIL-прогон
указателем требует наличия измеренной ошибки позиционирования, а не только
идентификатора калибровки. Реальный последовательный адаптер также обязан
требовать явный флаг конструктора `allow_hardware=True` перед открытием порта.

Команда `dry-run-plan` использует `DryRunSerialAdapter`, а не реальный
последовательный порт. При этом каждая команда из экспортированного
`ActionPlan` всё равно проходит через `SafetyGate`; результаты `ALLOW_DRY_RUN`
и `BLOCK_*` записываются в журнал команд и воспроизведение. После первой неуспешной
команды выполнение останавливается, чтобы пропущенные команды были явно видны в
отчётах.

`HumanReviewPolicy` не создаёт исполнимых команд. Это политика для оператора и
интерфейса, которая показывает цели, уже требующие проверки или отклонённые
построителем маски действий. Политики сохраняют структурированные
`review_reasons_by_target` и `blocked_reasons_by_target` в
`ActionPlan.metadata`, поэтому экспортированные планы и отчёты по сценариям
сохраняют причину проверки или блокировки каждой цели.

`configs/safety/safety_limits.example.yaml` загружается через
`seedling_decision.load_safety_limits`. Загрузчик отклоняет неизвестные поля,
небулевы переключатели безопасности, отрицательные пределы расстояний/ошибок и
режимы вне `simulation`, `dry_run_pointer`, `hardware_in_loop_pointer` и
`supervised_mark`. Телеметрия с неизвестным режимом робота блокируется как
`BLOCK_SYSTEM_ERROR` с причиной `invalid_robot_mode`.
